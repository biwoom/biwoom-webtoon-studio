# 제작 운영 흐름과 P5 인계 계약

G0 출전·권리·주제 → G1 대본 → G2 미술 기준 → **실제 시각 콘티 제작 → G3** → 후보 생성 → QA·수정 → **G3.5 현재 컷 이미지+대사** → 조판/Q4 → **G4 회차 최종 승인** → 로컬 완성본. 공개·GitHub push는 별도 명시적 승인이다. YAML만으로 시각 콘티를 대신하지 않는다.

## 실행마다 확인할 것
1. 실제 작업 루트, 사용자 최신 지시, 대본/콘티/이미지 버전, 예산·권리·허용 명령을 확인한다.
2. 대화의 창작 결정은 구조화된 연속성 원장에 출처·영향 컷을 기록한다. 원장과 실제 대본/이미지가 다르면 미반영으로 표시한다. 작품별 비공개 원장은 로컬에서 관리하며 보편 미술 규칙으로 간주하지 않는다.
3. 시각 콘티 연결본에서 동작·반응·화면축·시선·손 좌우·소품 수/소유자·임시 레터링·여백을 확인하고 G3를 받는다.
4. 생성 요청은 컷 ID·원장 규칙·참조 버전·프롬프트·결과 파일/해시·모델·비용을 연결한다. 외부 도구로 만든 결과도 provenance를 별도 수입해야 한다.
5. 자동 QA는 객관 검사를, 사람은 교학·미술·연출 판단을 맡는다. 수정은 영향 컷을 지정하고 앞뒤 컷과 다시 비교한다. 이미지 비교 없이 텍스트 보고만으로 시각 통과를 선언하지 않는다.
6. G3.5는 승인 주체/시각/대화 근거와 정확한 컷 ID·image revision/hash·dialogue revision/hash를 함께 기록한다. 이미지 단독 승인·모의 승인을 전체 조합 승인으로 확대하지 않는다. 원본과 과거 승인 기록은 불변으로 보존한다.
7. 조판 직전 실제 이미지 바이트와 대사+캡션 정규화 데이터의 해시를 재대조한다. 변경 컷은 재승인, 변경 없는 컷은 유지한다. 대사만 변경하면 이미지 재생성은 하지 않는다.
8. 미승인 검토용 결과와 G4 완성본을 분리한다. 파일럿을 테스트로 닫는 동의는 G4나 배포 승인이 아니다. Library 보관과 Mac 보관은 각각 실제 파일·해시·CRC 증거로 확인한다.

## 구체적인 P5
P5는 감독의 자연어를 권한·입출력·예산·완료 증거가 있는 작업 계약으로 바꾸고, 실행자에게 위임하고, 반환된 파일·해시·로그를 검증하며, 영향 컷/승인 대기를 추적하고 사용자에게 회차 보고를 전달하는 연결 계층이다.

이번 구현: 읽기 전용 `preflight/status ST-NNN`, 해시 바인딩 비교 함수, 영향 컷 조회 함수와 테스트. 상태 명령은 차단 항목이 있으면 exit 2, 입력/읽기 오류는 exit 1이다. 파일이나 승인 상태를 바꾸지 않으며 live/release는 항상 false다.

미구현: 인증된 사용자 승인 수입·실제 Dot→Codex 작업 실행/재개·중복 작업 방지·비용 승인·외부 생성 도구 provenance 수입·신뢰 가능한 자동 시각 QA·릴리스 조정. 함수의 해시 일치만으로 승인 주체의 진위를 인증할 수 없다. 기존 P0/P1 해시 규칙을 몰래 교체하지 않으며 P5의 비교 규칙은 별도 명시한다(UTF-8 JSON, sorted keys, compact separators, 대사+캡션 전체).

## 후속 P5/P6 작업 (이번에는 구현하지 않음)
- 단계별 retry 상한·pause/resume 상태·작업 idempotency key로 중복 provider queue를 막는다. 유료 재시도는 승인 범위 확인 없이 조용히 수행하지 않는다.
- approval missing / image-only / 정확한 현재 image+dialogue hash / changed artifact 상태를 구분한다. 해시 일치는 승인 주체 인증과 다르다.
- private pilot_closed와 G4를 구분하고, 승인·권리·비용·보관 상태를 독립 관리한다.
- 전체 렌더링 전에 행동→반응→드러남의 3컷 휴대폰 시각 콘티를 두 가지 간격으로 비교한다. 실제 연구·새 제작은 후속 승인 작업이며 이번 감사에서 실행하지 않았다.
